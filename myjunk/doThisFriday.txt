Implemented all **three layers** in the repo. They work together once you deploy HAProxy/PgBouncer on the servers and restart FE/BE.

---

## 1. PgBouncer (config + installer)

| File | Purpose |
|------|---------|
| `configSetup/pgbouncer/pgbouncer.ini` | **Session** pool → `127.0.0.1:50010` |
| `configSetup/pgbouncer/userlist.txt.example` | Auth template |
| `scripts/install-pgbouncer.sh` | Mac or Ubuntu install |

**Mac dev:** (Homebrew **or** MacPorts — this Intel Mac uses MacPorts; `/usr/local/bin/brew` is gone)

```bash
sudo port install pgbouncer
./scripts/install-pgbouncer.sh --mac
# Homebrew instead: brew install pgbouncer
```

Then in `~/.ssh/be/.env`: `DB_HOST=127.0.0.1`, `DB_PORT=6432`, restart `beall`.

**Ubuntu web box:**

```bash
sudo ./scripts/install-pgbouncer.sh
# DB_PORT=6432 in ~/.ssh/be/.env → pm2 restart tutamallPM2Process
```

PgBouncer is **not** running until you run the script on each host.

## 3. App overload + FE auto-retry (code — active after restart)

**Backend**

- `be/middleware/systemOverload.js` — if local pg pool **`waitingCount ≥ 8`** (default) or **busy ≥ 88%**, returns:
  - `503` + `code: SYSTEM_OVERLOADED` + `Retry-After`
- Mounted after `/health` routes (health stays exempt).
- Env: `SYSTEM_OVERLOAD_ENABLED` (default **on**), `SYSTEM_OVERLOAD_POOL_WAITING`, `SYSTEM_OVERLOAD_BUSY_PCT`, `SYSTEM_OVERLOAD_RETRY_AFTER_SEC`.

**Frontend**

- `SystemOverloadModal` — “System under heavy load… retrying automatically.”
- `axios` — up to **40** auto-retries on `SYSTEM_OVERLOADED` (no click spam).
- `serverDownError.js` — overload 503 is **not** “server down.”

Restart **beall** + **feall** (or deploy) to pick this up.

---

## How the three work together

```text
User → HAProxy (queue / maxconn 200 per box)
     → Node (overload 503 + JSON if DB pool saturated)
     → PgBouncer :6432 (when installed) → Postgres :50010
     → FE modal + auto-retry until success or max retries
```


**Note:** Overload middleware triggers on **per-worker** pool pressure (good for shedding); HAProxy caps **HTTP** concurrency; PgBouncer caps **Postgres** connections. None of that replaces a **job queue** for long LLM/backup work — that’s a separate follow-up.
